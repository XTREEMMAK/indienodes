# Web, Android, and desktop builds

IndieNodes has one SvelteKit frontend. The web/PWA build remains canonical, and
the Android and desktop projects are thin hosts around the same static output.
There are no copied Svelte source trees and no native implementation of ring,
player, discovery, or Ambient Mode behavior.

```text
SvelteKit source
      |
      v
  build/
   |   |
   |   +--> Capacitor sync --> Android project
   |
   +------> asset sync ------> Wails embed.FS
```

## Web

```bash
npm run dev
npm run build
npm run preview
```

`npm run build` prerenders every route with `adapter-static` into `build/`.
Native packaging consumes this exact output; it does not use a second SvelteKit
configuration or change the web deployment.

## Android / Capacitor

The Capacitor 8 configuration lives in `platforms/capacitor/`, and its custom
Android project path keeps generated native source beside that config. The
runtime and Android packages are normal root dependencies so the whole project
still has one lockfile.

The private manifest beside the Capacitor config exists only because the CLI
requires its working directory to be an npm package. It declares no dependencies
and does not introduce another frontend or lockfile.

```bash
npm run android:sync   # build the shared frontend and copy it into Android
npm run android        # build, install, and run on a selected device/emulator
npm run android:open   # sync and open the project in Android Studio
npm run android:build  # produce a release build through Capacitor
```

Capacitor requires Node 22 or newer. Building or launching Android also requires
the JDK, Android Studio/SDK, and a configured device or emulator. Run
`node scripts/platforms/run-capacitor.mjs doctor android` after installing that
toolchain. The repository can still build and synchronize web assets when the
native compiler is unavailable.

The package id is `us.indienodes.app`. Changing it after publishing an Android
application creates a different app identity, so treat it as a release-level
decision.

## Desktop / Wails

The desktop host targets stable Wails v2.13.0. Wails v3 is still alpha and uses
a different project/build layout, while this repository's architecture is
deliberately based on the stable v2 `wails.json` contract.

```bash
npm run desktop:assets # build once and copy build/ into Wails' embed directory
npm run desktop        # run wails dev from platforms/wails
npm run desktop:build  # compile a native executable
```

Install Go and Wails before running the last two commands:

```bash
go install github.com/wailsapp/wails/v2/cmd/wails@v2.13.0
wails doctor
```

Wails requires Go 1.21 or newer plus platform-specific webview/build packages.
On Linux, `wails doctor` identifies the GTK/WebKit packages for the current
distribution. On Windows it checks WebView2, and on macOS it checks the Xcode
command-line tools. `go.sum` is generated by the first `go mod tidy` or Wails
build on a machine with Go installed; it is intentionally not fabricated by a
Node-only environment.

`platforms/wails/frontend/dist/` is generated and ignored. The sync script
refuses to write outside `platforms/wails/`, clears only that exact destination,
copies the canonical `build/`, and verifies that the copied `index.html` exists.

## Current compatibility boundary

- Shared browser functionality remains unchanged and is the only application
  implementation.
- Native packaging is optional; `npm run dev` and `npm run build` do not require
  Go, Java, Android Studio, Wails, or a native SDK.
- No platform abstraction exists yet because the app does not currently call a
  native-only capability. Add an adapter when a real feature such as keep-awake,
  native media controls, filesystem caching, or window management requires one.
- External links and media retain their existing browser behavior. Native
  open-external handling should be introduced with the first platform adapter,
  not as scattered component checks.
- The PWA currently consists of the web manifest and install icons; there is no
  service worker or offline cache to disable or duplicate inside native hosts.

## Version synchronization

The application version is canonical in root `package.json`. Native release
metadata must match it when cutting a distributable build:

- Android: `platforms/capacitor/android/app/build.gradle`
- Capacitor host: `platforms/capacitor/package.json`
- Wails: `platforms/wails/wails.json` under `info.productVersion`

Android `versionCode` is an independent monotonically increasing store build
number; it starts at `1` for this scaffold.
